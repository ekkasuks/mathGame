# นักผจญภัยคณิต (Math Explorer) — เอกสารออกแบบ

**วันที่:** 2026-08-27
**สถานะ:** รออนุมัติสเปก
**ประเภท:** โปรเจกต์ใหม่ (Architectural)

---

## 1. ภาพรวมและเป้าหมาย

เกมฝึกทักษะคณิตศาสตร์ **บวก ลบ คูณ หาร** สำหรับนักเรียน **ป.3–ป.6** แนวผจญภัย/สำรวจโลก
(Sandbox & Creative) นักเรียนลงทะเบียนเล่น เก็บสถิติคะแนน และจัดอันดับเทียบกับเพื่อน

**เป้าหมายหลัก**
- ให้เด็กฝึกเลข 4 ชนิดอย่างสนุก ผ่านการสำรวจแผนที่และปลดล็อกด่าน
- เก็บคะแนนสะสมและจัดอันดับ (leaderboard) เพื่อสร้างแรงจูงใจ
- มีพื้นที่ให้เด็กสร้างสรรค์อิสระ (ฐานผจญภัย + แต่งตัวละคร)
- โฮสต์ฟรีบน **GitHub Pages** เก็บข้อมูลใน **Google Sheets** ผ่าน **Google Apps Script**
- ครูดูแล/ปรับแต่งต่อเองได้ง่าย (ไม่มี build step)

**กลุ่มผู้ใช้:** นักเรียน ป.3–ป.6 เล่นทั้งบนมือถือและคอมพิวเตอร์ (responsive)

## 2. การตัดสินใจเชิงสถาปัตยกรรม

| หัวข้อ | การตัดสินใจ | เหตุผล |
|--------|-------------|--------|
| เทคโนโลยีหน้าเว็บ | Vanilla HTML/CSS/JS ไม่มี build step | ง่าย ฟรี ดูแลต่อเองได้ โหลดเร็ว ไม่มี toolchain ให้พัง |
| โฮสติ้ง | GitHub Pages | ฟรี เสิร์ฟ static ได้ตรงๆ |
| Backend/ฐานข้อมูล | Google Apps Script Web App + Google Sheet | ฟรี, Sheet เป็นฐานข้อมูล, GAS เป็นตัวกลางที่ปลอดภัย |
| การเข้าสู่ระบบ | ชื่อ + PIN 4 หลัก (เก็บ pinHash) | เด็กเข้าง่าย กันสวมรอยได้พอสมควร |
| ความยากโจทย์ | ไล่ตามโซน/ด่านของแผนที่ | ผูกกับการผจญภัยอย่างเป็นธรรมชาติ |
| การจัดอันดับ | คะแนนสะสมรวม (leaderboard เดียว) | เรียบง่าย เข้าใจง่ายสำหรับเด็ก |

## 3. การออกแบบเกม

### 3.1 โครงโลกและโซน (ไล่ความยาก)

แผนที่โลกแบ่งเป็น 4 โซน ธีมต่างกัน ไล่ความยากขึ้น (คร่าวๆ ตามระดับชั้น
แต่ทุกคนเล่นได้ทุกโซนที่ปลดล็อกแล้ว):

| โซน | ธีม | เนื้อหาเลข | ระดับ | ตัวคูณคะแนน |
|-----|-----|-----------|-------|-------------|
| 🌳 โซน 1 | ป่าเริ่มต้น | บวก/ลบ หลักเดียว–สองหลัก | ~ป.3 | ×1 |
| 🏜️ โซน 2 | ทะเลทราย | บวก/ลบ หลายหลัก + คูณเบื้องต้น (สูตรคูณ) | ~ป.4 | ×2 |
| 🌊 โซน 3 | มหาสมุทร | คูณ/หาร | ~ป.5 | ×3 |
| 🏔️ โซน 4 | ยอดเขา/อวกาศ | ผสมทั้ง 4 แบบ + โจทย์ท้าทาย | ~ป.6 | ×4 |

แต่ละโซนมีหลายด่าน (จุดบนเส้นทาง) แต่ละด่าน = ชุดโจทย์ ~8–10 ข้อ

### 3.2 Loop การเล่นหลัก

1. เข้าเกม → เห็นแผนที่โลกพร้อมความคืบหน้าของตัวเอง
2. เลือกด่านที่ปลดล็อกแล้ว
3. ตอบโจทย์ในด่าน (สุ่มสร้างสดตามชนิด/ความยากของด่าน)
4. ตอบถูก → ได้คะแนน + เหรียญ + ดาว → ปลดล็อกด่านถัดไป
5. คะแนนสะสมรวม → ขึ้นกระดานอันดับ

### 3.3 องค์ประกอบ "โลกเสรี + สร้างสรรค์" (Sandbox/Creative)

- **สำรวจอิสระ** — ในโซนที่ปลดล็อกแล้ว เลือกเล่นด่านไหนก่อนก็ได้ เล่นซ้ำเก็บคะแนนได้
- **ฐานผจญภัยส่วนตัว** — เอาเหรียญไปซื้อของตกแต่ง (ต้นไม้ ธง สัตว์เลี้ยง) มาจัดวางเอง
  อย่างอิสระในฐานของตัวเอง + แต่งตัวละคร (ส่วนนี้พัฒนาในเฟสหลัง — M5)

### 3.4 ระบบคะแนน

- ตอบถูก = `คะแนนฐาน × ตัวคูณความยากของโซน`
- ตอบถูกติดกัน = โบนัส streak เล็กน้อย (เช่น ทุก 5 ข้อติด +โบนัส)
- ตอบผิด = ไม่ได้คะแนน (ไม่หักคะแนน เพื่อไม่ให้เด็กท้อ) เฉลยแล้วไปต่อ
- ได้เหรียญคู่ขนานกับคะแนน (ใช้ซื้อของตกแต่งฐาน)

### 3.5 การสร้างโจทย์ (สำคัญ)

โจทย์ **สุ่มสร้างสดด้วย JavaScript** (`questions.js`) ตามพารามิเตอร์ความยากของแต่ละด่าน
— ไม่เก็บคลังข้อสอบที่ใดเลย ทำให้ Google Sheet เก็บแค่ข้อมูลนักเรียนกับคะแนน

**ข้อกำหนดการสร้างโจทย์:**
- บวก/ลบ: ควบคุมช่วงตัวเลขตามโซน; การลบไม่ให้ผลลัพธ์ติดลบสำหรับโซนต้นๆ
- คูณ: ควบคุมช่วงตัวตั้ง/ตัวคูณ (โซน 2 เน้นสูตรคูณ 2–12)
- หาร: ต้องหารลงตัว (ไม่มีเศษ) สำหรับ ป.3–5; โจทย์เศษเฉพาะโซนท้ายถ้าต้องการ
- คำตอบที่ถูกต้องคำนวณควบคู่ตอนสร้างโจทย์เสมอ (verifiable)

## 4. สถาปัตยกรรมเทคนิค

### 4.1 ภาพรวมการเชื่อมต่อ

```
[เบราว์เซอร์เด็ก] ⇄ [GitHub Pages: หน้าเว็บ static]
        │
        │ fetch (HTTPS, simple request)
        ▼
[Google Apps Script Web App = API] ⇄ [Google Sheet (ข้อมูลจริง, ส่วนตัว)]
```

Sheet ตั้งเป็นส่วนตัว มีแค่ GAS เท่านั้นที่แตะได้ หน้าเว็บไม่ถือกุญแจ Sheet

### 4.2 โครงไฟล์ฝั่งหน้าเว็บ (ไม่มี build step)

```
index.html            หน้าเข้าเกม (login/register) + คอนเทนเนอร์หน้าจอเกม
config.js             URL ของ GAS + ค่าคงที่ (ปรับที่เดียว)
css/styles.css
js/
  app.js              ตัวคุมหลัก สลับหน้าจอ (router อย่างง่าย)
  api.js              คุยกับ GAS (fetch + retry + error mapping)
  auth.js             ลงทะเบียน/เข้าสู่ระบบ + จำ session (localStorage)
  world.js            แผนที่โลก/โซน/ความคืบหน้า
  questions.js        เครื่องสุ่มสร้างโจทย์ตามความยาก (logic ล้วน, ทดสอบได้)
  game.js             loop เล่นด่าน (ถาม-ตอบ-ให้คะแนน)
  scoring.js          ตรรกะคำนวณคะแนน/streak/ตัวคูณ (logic ล้วน, ทดสอบได้)
  leaderboard.js      ดึง+แสดงกระดานอันดับ
  base.js             ฐานผจญภัย + แต่งตัวละคร (เฟสหลัง M5)
  storage.js          แคชความคืบหน้าออฟไลน์ + คิวส่งซ้ำ
assets/               รูป ไอคอน เสียง
```

หลักการแยกส่วน: `questions.js` และ `scoring.js` เป็น pure logic ไม่พึ่ง DOM/เครือข่าย
เพื่อให้ทดสอบง่ายและเปลี่ยนภายในได้โดยไม่กระทบส่วนอื่น

### 4.3 โครงสร้าง Google Sheet

**แท็บ `Players`** (1 แถว = 1 นักเรียน)

| คอลัมน์ | ชนิด | หมายเหตุ |
|---------|------|----------|
| studentId | string | คีย์หลัก (สร้างตอน register เช่น uuid สั้น) |
| displayName | string | ชื่อที่แสดง |
| grade | number | 3–6 (ไว้ให้ครูกรอง/ดูสถิติ) |
| pinHash | string | SHA-256 ของ (PIN + salt) — ไม่เก็บ PIN ดิบ |
| totalScore | number | คะแนนสะสมรวม (ใช้จัดอันดับ) |
| coins | number | เหรียญสะสม |
| progressJSON | string(JSON) | ด่าน/โซนที่ผ่าน, streak สูงสุด ฯลฯ |
| baseJSON | string(JSON) | ของตกแต่งฐาน + ตัวละคร (เฟสหลัง) |
| createdAt | timestamp | |
| updatedAt | timestamp | |

**แท็บ `Log`** (ตรวจสอบ/กันโกงเบาๆ): `timestamp | studentId | action | detail`

การเก็บ `progressJSON`/`baseJSON` เป็น JSON ก้อนเดียวช่วยให้เพิ่ม/เปลี่ยนโครงข้อมูลเกม
ได้โดยไม่ต้องแก้สคีมา Sheet

### 4.4 API ของ GAS (route ด้วยพารามิเตอร์ `action`)

| action | ขาเข้า | ขาออก | หน้าที่ |
|--------|--------|-------|---------|
| `register` | name, grade, pin | ok, profile | สร้างนักเรียนใหม่, เก็บ pinHash, กันชื่อซ้ำ |
| `login` | name, pin | ok, profile+progress | ตรวจ hash, คืนสถานะล่าสุด |
| `submitProgress` | studentId, token, delta(score/coins/stage) | ok, newTotals | บันทึกความคืบหน้า (เฉพาะส่วนที่เปลี่ยน) |
| `getLeaderboard` | top(N) | ok, rows[] | คืน Top N เรียงตาม totalScore (มีแคช) |
| `getProfile` | studentId, token | ok, profile+progress | ดึงสถานะล่าสุด (สลับเครื่อง) |

รูปแบบผลลัพธ์มาตรฐาน: `{ ok: true, data: {...} }` หรือ `{ ok: false, error: "รหัสข้อผิดพลาด" }`

### 4.5 การไหลของข้อมูล

- **เข้าเกม:** ส่งชื่อ+PIN → GAS ตรวจ hash → คืนโปรไฟล์ → เก็บ session ใน localStorage
- **เล่นด่าน:** โจทย์สุ่มในเครื่อง → จบด่านคำนวณคะแนน → อัปเดต localStorage ทันที
  → ส่ง `submitProgress` เบื้องหลัง
- **อันดับ:** ดึงจาก GAS (แคช) มาแสดง

## 5. ทำงานร่วมกับ Google Sheets ให้ลื่นไหล

ปัญหาหลัก: GAS ช้า (300ms–2s/ครั้ง) และเขียนชนกันเมื่อหลายคนเล่นพร้อมกัน
รับมือ 6 ชั้น:

1. **Optimistic UI** — คะแนน/ความคืบหน้าอัปเดตบนจอทันทีจาก localStorage แล้ว sync
   ขึ้น Sheet เบื้องหลัง เกมไม่รอเน็ต
2. **ยิง API ให้น้อยที่สุด** — โจทย์สุ่มในเครื่อง; บันทึกแค่ตอนจบด่าน; ส่งเฉพาะ delta;
   debounce เมื่อเล่นหลายด่านติดกัน
3. **ค้นหานักเรียนเร็ว** — ใช้ `TextFinder` หา studentId ในคอลัมน์เดียว แทนอ่านทั้งชีต
4. **แคช leaderboard ใน GAS** — `CacheService` cache ~30–60 วินาที
5. **LockService** — ล็อกสั้นๆ ตอนเขียน กัน race condition หลายคนจบด่านพร้อมกัน
6. **อ่าน/เขียนเป็นช่วง (batch)** — ใช้ `getValues()/setValues()` กับ range ไม่แตะทีละเซลล์

## 6. การจัดการข้อผิดพลาด & ออฟไลน์

- ส่งข้อมูลไม่สำเร็จ → เก็บเข้าคิวใน localStorage แล้วลองส่งซ้ำอัตโนมัติ (retry + backoff)
  ไม่เสียความคืบหน้า
- GAS คืน error เป็น JSON รูปแบบเดียว `{ok:false, error:"..."}`
- แจ้งเตือนเป็นภาษาเด็กเข้าใจ ("เน็ตมีปัญหา เดี๋ยวลองใหม่ให้นะ") ไม่ใช่ error ดิบ
- ตรวจ input ทั้งฝั่ง client และ GAS (ชื่อซ้ำ, PIN ต้อง 4 หลัก, grade 3–6)

## 7. ความปลอดภัย (ระดับเหมาะกับเกมในโรงเรียน)

- **PIN** — ไม่เก็บดิบ เก็บเป็น SHA-256(PIN + salt) ; ย้ำกับครูว่า PIN นี้เป็นระดับ
  "กันสวมรอยในห้อง" ไม่ใช่รหัสผ่านความปลอดภัยสูง เด็กไม่ควรใช้ PIN ซ้ำกับบัญชีสำคัญ
- **Sheet ส่วนตัว** — เข้าถึงผ่าน GAS เท่านั้น (Execute as owner, ใครก็เรียก endpoint ได้
  แต่แตะ Sheet ตรงไม่ได้)
- **กันโกงเบาๆ** — คะแนนส่งจาก client แก้ได้ ในบริบทนี้ยอมรับได้ แต่ GAS จะตรวจ
  ความสมเหตุสมผล (เพดานคะแนนต่อการส่ง) + เก็บ Log ไว้ตรวจย้อนหลัง

## 8. การทดสอบ

- **`questions.js`** — โจทย์แต่ละโซนอยู่ในช่วงความยากที่กำหนด, ลบไม่ติดลบ/หารลงตัว
  ตามระดับ, คำตอบถูกต้องเสมอ (unit test)
- **`scoring.js`** — คำนวณคะแนน/streak/ตัวคูณถูกต้อง (unit test)
- **GAS** — ทดสอบ register/login/submit ด้วยฟังก์ชันทดสอบใน GAS editor + Sheet ทดลอง
- **Responsive** — ทดสอบบนมือถือจริง + คอมพิวเตอร์

## 9. ลำดับการพัฒนา (Milestones)

| # | ชื่อ | ขอบเขต |
|---|------|--------|

## 10. ขอบเขตที่ "ไม่ทำ" ในเวอร์ชันนี้ (YAGNI)

- ไม่มีระบบ leaderboard หลายแบบ (เอาเฉพาะคะแนนสะสมรวม)
- ไม่มีการปรับความยากอัตโนมัติ (adaptive) — ใช้ความยากตามโซน
- ไม่มีระบบครู/แดชบอร์ดครูแยก (ครูดูข้อมูลผ่าน Sheet โดยตรงในเวอร์ชันนี้)
- ไม่มีเสียง/แอนิเมชันหนักแบบเกมเอนจิน
- ไม่มี multiplayer เรียลไทม์
